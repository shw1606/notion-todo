# 결정 기록 (ADR)

새 결정은 맨 위에 추가. 날짜는 절대값으로 쓴다.

## 2026-11-08 — 중계 서버를 먼저 세운다

**결정:** 클라이언트 경로(A/B)를 확정하기 전에 셀프호스팅 중계 API를 먼저 만든다.

**근거:** 위젯 쪽 제약(Apple 빌드 환경·서명 계정·WidgetKit 갱신 예산)은 클라이언트 레이어에만
걸린다. 서버는 A·B 어느 쪽에서도 그대로 쓰이므로 선택을 미뤄도 작업이 낭비되지 않는다.
반대로 클라이언트를 먼저 만들면 Notion 레이트리밋을 직접 맞는 구조가 되어 재작업이 생긴다.

## 2026-11-08 — Notion webhook + 폴링 백업 병행

**결정:** `data_source.content_updated` webhook을 1차 신호로 쓰고, 저빈도 폴링을 백업으로 둔다.

**근거:** webhook은 이벤트가 집계(aggregate)되어 들어오고 페이로드가 메타데이터뿐이라
유실·누락 시 상태가 조용히 어긋난다. 폴링 백업이 있으면 최악의 경우에도 수렴한다.

## 2026-11-08 — 중계 서버는 loopback 바인딩 + 인증 프록시로만 노출

**결정:** 중계 API는 `127.0.0.1`에 바인딩하고, 외부 접근은 인증이 걸린 리버스 프록시
(또는 사설 네트워크 터널)를 통해서만 허용한다. 클라이언트는 API 키를 제시한다.

**근거:** Notion 인티그레이션 토큰을 보유한 프로세스다. 공개 인터넷에 직접 바인딩하면
토큰 권한 범위 전체가 노출면이 된다.
